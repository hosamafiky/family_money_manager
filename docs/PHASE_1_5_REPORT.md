## 1. EOL-Package Interpretation Correction

### Previous (incorrect) conclusion

The Phase 1 `DECISION_004_ASSESSMENT.md` stated that encrypted Drift databases were
"unavailable" because `sqlite3_flutter_libs` and `sqlcipher_flutter_libs` were
end-of-life (EOL).

### Corrected understanding

`sqlite3_flutter_libs` and `sqlcipher_flutter_libs` are **obsolete compatibility
packages** that existed under the `sqlite3` 2.x platform-build-script scheme.
They are marked `+eol` on pub.dev because that scheme has been replaced.

Under `sqlite3` 3.x, SQLite is bundled via **Dart pub build hooks** (native assets).
The two EOL packages remain as no-op transitive stubs when `drift_flutter` is resolved,
but they provide no native binary and do not affect the encryption result.

The correct path to encrypted databases is:

```yaml
# pubspec.yaml
hooks:
  user_defines:
    sqlite3:
      source: sqlite3mc   # SQLite3MultipleCiphers
```

**Claim classification:** Documented only (conceptual correction to prior error).

## 8. Typed-Navigation Evidence

### Previous implementation (Phase 1)

The Phase 1 implementation used a handwritten `sealed class AppRoute` with a manual
`go(context)` method that called `GoRouter.of(context).go(path)`. This was
compile-time safe for the path type but did not use GoRouter's official typed routing
and did not support typed route parameters.

### Phase 1.5 implementation

Replaced with **GoRouteData** using `go_router_builder 4.3.1`.

**Route definitions (`lib/core/navigation/routes.dart`):**

```dart
@TypedGoRoute<SmokeRouteData>(
  path: '/',
  routes: [TypedGoRoute<FoundationDetailRouteData>(path: 'detail/:probeId')],
)
class SmokeRouteData extends GoRouteData with $SmokeRouteData { ... }

class FoundationDetailRouteData extends GoRouteData with $FoundationDetailRouteData {
  final String probeId;
  ...
}
```

**Generated file (`lib/core/navigation/routes.g.dart` — do not edit):**

- `List<RouteBase> get $appRoutes` — registered in `AppRouter.create()`
- `mixin $SmokeRouteData` — provides `String get location => '/'`, `.go()`, `.push()`
- `mixin $FoundationDetailRouteData` — parses `probeId` from `state.pathParameters['probeId']`; encodes to `/detail/<URI-encoded probeId>`

**Navigation calls are typed:**

- `const SmokeRouteData().go(context)` — replaces raw `GoRouter.of(context).go('/')`
- `FoundationDetailRouteData(probeId: 'abc').go(context)` — typed parameter, no string concatenation

**Parameter serialization evidence:**

| Expression | Location | Classification |
|---|---|---|
| `const SmokeRouteData().location` | `'/'` | Unit-tested |
| `FoundationDetailRouteData(probeId: 'abc123').location` | `'/detail/abc123'` | Unit-tested |
| `FoundationDetailRouteData(probeId: 'hello world').location` | `'/detail/hello%20world'` | Unit-tested |
| Round-trip: location → URI decode → probeId | matching | Unit-tested |

**Deleted:** `lib/core/navigation/app_route.dart` (Phase 1 sealed-class approach)

## 9. Key-Management Recommendation

See `docs/LOCAL_ENCRYPTION_KEY_MANAGEMENT.md` for the full proposed architecture.

Summary:

- Random 256-bit DEK generated via `Random.secure()`
- Android: Keystore-wrapped DEK stored via `flutter_secure_storage`
- iOS: DEK stored directly in Keychain with `.biometryCurrentSet` access control
- PIN gates the app-lock UI; it does not derive or wrap the database key
- Biometric authentication gates OS release of the stored key
- Backup uses a separate recovery passphrase (not the DEK)
- Lost device-bound key → local data unrecoverable without backup or cloud sync

**Claim classification:** Documented only. Not implemented. Not tested.
